====================================================
PROBLEME A CORRIGER
====================================================

Aujourd'hui le module CashTransfer représente seulement le document métier du transfert.

Je veux maintenant que les impacts financiers soient enregistrés sous forme d'opérations de caisse.

Autrement dit :

UN TRANSFERT NE MODIFIE JAMAIS DIRECTEMENT LE SOLDE.

Le solde d'une caisse doit toujours être calculé uniquement à partir des CashOperation.

====================================================
NOUVELLE REGLE METIER
====================================================

Lorsqu'un transfert devient COMPLETED
(ou APPROVED si l'application ne distingue pas ces deux états),

le système doit créer automatiquement deux opérations.

====================================================
OPERATION 1
====================================================

CashOperation

Type :
TRANSFER_OUT

CashRegister :
Source

Montant :
Montant du transfert

Référence :
TransferRef

CashTransferId :
Id du transfert

Description :
Transfert vers la caisse XXX

Catégorie :
Transfert

====================================================
OPERATION 2
====================================================

CashOperation

Type :
TRANSFER_IN

CashRegister :
Destination

Montant :
Montant du transfert

Référence :
TransferRef

CashTransferId :
Id du transfert

Description :
Transfert depuis la caisse XXX

Catégorie :
Transfert

====================================================
CONTRAINTES
====================================================

Les deux opérations doivent être créées dans UNE transaction EF Core.

Si une opération échoue :

aucune des deux ne doit être enregistrée.

Le CashTransfer ne doit pas passer à COMPLETED.

====================================================
WORKFLOW
====================================================

Cas sans validation

Création transfert

↓

Validation automatique

↓

Création des deux CashOperation

↓

COMPLETED

----------------------------------------------------

Cas avec validation

Création

↓

PENDING_APPROVAL

↓

AUCUNE opération créée

↓

Approbation

↓

Création des deux CashOperation

↓

COMPLETED

----------------------------------------------------

Cas rejet

Création

↓

PENDING

↓

REJECTED

↓

Aucune CashOperation

====================================================
ANNULATION
====================================================

Si un transfert COMPLETED est annulé
(selon les droits),

le système ne doit jamais supprimer les opérations.

Il doit créer deux opérations inverses :

TRANSFER_OUT_REVERSAL

TRANSFER_IN_REVERSAL

afin de conserver une parfaite traçabilité.
